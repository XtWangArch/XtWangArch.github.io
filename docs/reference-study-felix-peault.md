# Felix Peault 摄影网站参考研究

研究日期：2026-11-01  
参考站：https://felixpeault.com/  
用途：讨论 Xitao Wang 网站摄影分支的设计方向。本报告不是实施方案批准，也没有修改现有页面。

## 1. 结论先行

这个网站的核心不是「极简背景 + 图片网格」，而是一个把摄影师身份、编辑策展和照片归档分开的观看系统：

- 首页先传达作者的观看方式，不急着给出完整作品目录。
- Series 是经过编辑的主题系列，采用一次专注观看一组、再一次观看一张的节奏。
- Elsewhere 是按地点组织的照片档案，先提供高密度接触印样式总览，再进入连续的大图阅读。
- Info 是随时可以打开的作者与联系信息层，不与照片争夺默认画面。

我的判断：最适合借鉴的是这套「精选 / 归档」双轨内容结构、照片原比例展示、低干扰导航和保留浏览位置的返回逻辑。彩色渐变、巨大的 F/P 标识和窄粗字体是作者本人的视觉身份，不需要原样搬到你的网站。

## 2. 核验范围与边界

本次检查包括：

- 桌面 1440 × 1000，以及手机尺寸 393 × 852 的页面截图与布局。
- 首页、Series 目录、系列详情、Elsewhere 目录、地点相册、Info、单张照片放大层。
- 5 个主题系列和 12 个地点相册的公开路由，均返回 HTTP 200。
- 实际操作菜单展开、系列目录滚动、序号跳转、系列缩略图、方向键、滚轮切图、Details 展开、XS/SM/MD 切换、相册滚动计数、照片放大、Escape 返回及 Info 关闭。
- 读取公开 HTML/CSS，核对字体、颜色变量、图片响应式资源和部分过渡参数。

边界：不是逐张评审全部摄影作品；其余系列通过路由与模板结构核对，交互深查主要使用第一个主题系列和 Thailand 相册。手机检查是 Chromium 的手机尺寸模拟，不等于 iPhone Safari 真机验收；没有进行完整 Lighthouse、屏幕阅读器或网络性能审计。

## 3. 网站完整层级

```text
首页 /
  Series /series
    主题系列 /series/{series-slug}
      Details：系列说明展开层
      当前照片状态 #{photo-number}
      单张放大 /series/{series-slug}/{photo-number}

  Elsewhere /journeys
    地点相册 /journeys/{place-slug}
      单张放大 /journeys/{place-slug}/{photo-number}

  Info /info
    作者介绍、拍摄方向、合作范围、联系方式
```

这里同时存在「页面路由」和「覆盖在原页面上的界面层」。例如从 Series 打开 Info，URL 会变成 `/info`，但原来的 Series 页面仍保留在后面；关闭时可以回到原来的页面，而不是重新开始浏览。

### Series 的内容组织

目前有五个主题系列：Outskirts of Eden、Ordinary Oddities、Angles of Incident、Graphic Matter、Slow Structures。年份既有单年，也有跨年范围。这说明分类依据是视觉主题和创作命题，而不只是旅行发生的时间。[Series 目录](https://felixpeault.com/series)

### Elsewhere 的内容组织

目前有 12 个地点集合：Thailand、Vietnam、Australia、USA、New Zealand、Paris、France、Toulouse、Denmark、Italy、Amsterdam、Norway。它们混合城市与国家，不是严格的国家地理树，而是摄影师自己的旅行档案单位。地点旁边的数字表示照片数量，不是年份。[Elsewhere 目录](https://felixpeault.com/journeys)

## 4. 全局设计语言

### 4.1 页面像展场，不像项目卡片列表

照片没有装进圆角卡片，也没有每张图片都加标题、摘要、标签、按钮。布局依靠图像大小、边缘对齐和留白组织，不依靠大量边框。

界面提供几个稳定位置：作者标记、当前栏目、作品名称、当前图片编号。照片变化时，这些位置保持可识别，使浏览者始终知道自己在哪里。

### 4.2 色彩不是纯白，也不是一直铺满渐变

公开样式中的基础色包括：

| 用途 | 色值 | 观察 |
| --- | --- | --- |
| 深色文字 | `#222222` | 非纯黑的深色 |
| 基础底色 | `#f7eeec` | 很浅的粉灰色，不是纯白 |
| 全局蓝色 | `#007cba` | 首页与信息层的色彩来源之一 |
| 全局绿色 | `#00ba82` | 与蓝色形成渐变 |

首页的蓝绿渐变更明显；Series 的色彩多作为画面边缘的渐变带，并且不同系列有各自的颜色；Elsewhere 的目录和相册更接近安静的浅底；Info 的大面积蓝绿背景重新强化作者身份。

设计作用：用色彩区分观看状态，但不持续用高对比背景包围所有照片。它不是全站固定一个渐变背景。

### 4.3 字体用来建立识别，而不是制造很多层级

公开样式声明：标题字体为 `Suisse Intl Cond`，正文字体为 `Archivo`。标题视觉上窄而有力度，与图片的宽幅构图形成对照。字体文件中可见 Suisse 的 Bold 资源，因此不能仅根据部分元素计算样式显示的 `400` 就把它理解为细体。

在本次桌面尺寸下，栏目和系列目录标题约 25.6px，详情标题约 34px，说明性正文接近 16px；大段作者宣言明显更大。数字只是本次采样，不应当作全设备固定字号配方。

它的主要层级是：作者宣言 / 作品标题 / 年份与地点 / 计数。没有把每一个小字段做成新的视觉层级。

### 4.4 版式有网格，但不让网格本身被看见

基础样式设置桌面 16 列、手机 8 列的布局变量，桌面外边距 16px、手机 8px。画面中有很大的空白，不代表没有对齐规则。

值得区分：页面外边距很小，但主要作品区域仍有大量侧向留白。它利用边缘放置品牌和导航，把中心留给照片，而不是让所有照片都贴着屏幕边缘。

## 5. 首页：先建立摄影师的视角

桌面上，巨大 F 与 P 分别占据左上、左下位置；中央是叠放切换的摄影作品；底部是一段大号、紧行距的观看宣言；右侧中部是精简导航。[参考首页](https://felixpeault.com/)

中央照片会自动切换，图片层之间使用透明度、位移和缩放形成交接。整块照片区域可以进入 Series。这个入口不是需要读完说明才懂的按钮，而是作品本身。

手机上，F/P 移到顶部左右两端，照片位于中段，宣言和三个导航入口放在下方。它没有把桌面所有固定元素按比例缩小，而是重排了区域。

设计逻辑：第一眼建立记忆，第二步才进入作品分类。因为你的主站已经有视频封面、Profile 和 Portfolio 选择页，摄影分支不一定需要再复制一个完整的摄影首页，否则进入作品的路径会过长。

## 6. Series 目录：每个系列是一张封面

### 桌面排版

- 中央一张主要封面图。
- 图片下沿之外，左侧是系列名称，右侧是年份。
- 作者简介留在左边，当前栏目留在右边。
- 底部一排小圆点指示当前系列；当前项以实心形态区分。
- 滚动切换当前系列，图像、名称与年份一起交接。

在采样桌面中，封面图大约占视口宽度的一半。图像主体比文字重要，但没有强行铺满屏幕。

### 交互

滚动驱动系列切换，底部序号按钮可直接跳到指定系列。点击封面或名称进入对应系列。系列切换伴随透明度和变换过渡，不是普通静态长列表。

一次较大的滚轮输入在测试中可以跨越不止一个系列，因此不应把它描述成「不管滚多少都只走一个项目」的严格分页器。

### 对你的网站的启发

这与现有 Architecture 列表的一屏一项目节奏有相似之处，但摄影不需要把 Year / Type / Role 等建筑元信息长期放在封面旁边。系列名称、时间范围和可选地点已经足够。

## 7. 系列详情：单张观看 + 缩略图导航

以第一个系列为例，页面顶部居中显示标题和年份，旁边提供 Details；中间展示一张大图；底部是缩略图带；角落是当前张数 / 总张数。[系列详情示例](https://felixpeault.com/series/outskirts-of-eden)

### 图像处理

普通系列浏览使用 `object-fit: contain` 一类约束，横图与竖图保留自身比例，在共同的展示区域中适配。重点不是每张图占同样多面积，而是不要破坏构图。

### 已实测的切换方式

- 点击缩略图可换图，计数跟随变化。
- 键盘右方向键可切换到下一张。
- 滚轮在这个模式中用来切换照片，而不是滚出一条普通长页面。
- 当前照片编号会体现在 URL 的 hash 中，例如 `#03`。
- 点击主图可进入单张放大层，地址变成带照片编号的子路径。
- 从放大层按 Escape 可以返回系列，并保留当前照片状态。

缩略图围绕当前项展示，远处项会淡出、缩小或隐藏，不是把十几张图以同等强度堆在屏幕底部。

### Details 不是普通悬浮小弹窗

打开后，顶部出现大段系列说明、地点与年份，原来的照片浏览界面向下移动并淡化。信息与照片属于不同观看状态。关闭后回到看图。

这使作品说明在需要时足够有分量，但默认不占照片的空间。

## 8. Elsewhere 目录：接触印式照片档案

桌面布局是左侧地点名称与数量、右侧该地点的一整组小缩略图。各地点依次向下排列，不使用一张封面概括整组照片。[Elsewhere 目录](https://felixpeault.com/journeys)

它看起来像摄影工作中的接触印或底片筛选页，允许观众先扫描颜色、光线和题材，再决定进入哪一组。

### 不是 Pinterest 瀑布流

这里的关键是小图以接近统一的行高排列，横竖图的宽度随比例变化，再换行。不是各列独立向下堆叠高低不齐的卡片瀑布流。

### XS / SM / MD

桌面右下角的三个选项实际改变缩略图显示尺寸和密度：小尺寸适合快速扫完整个地点，大尺寸适合看更多细节。它改变的是观看尺度，不是分类过滤。

手机上这组尺寸控制隐藏，地点标题和数量移到照片组上方，缩略图仍是紧凑的多图总览，而不是简单变成一列超大照片。

目录中缩略图组链接到对应地点相册。不要把这里每张缩略图都默认理解为「直达这张照片」的独立入口。

## 9. 地点相册：连续大图阅读

进入地点相册后，照片按顺序纵向排列，中心列大约占桌面视口宽度的 60%，图片保留自然比例。上一张和下一张可以同时出现在视口中，这是它有意采用的连续阅读方式。[Thailand 相册](https://felixpeault.com/journeys/thailand)

左侧显示地点与计数；向下滚动时，计数随当前观看位置更新。右侧保留 Elsewhere 返回入口。

手机端大图基本占满可用宽度，左右保留小边距；标题与计数重排到图像区域上方。它保留了自然滚动，没有把桌面系列查看器强行用于所有相册。

这里与 Series 的区别非常重要：

| 问题 | Series | Elsewhere 相册 |
| --- | --- | --- |
| 内容目的 | 表达一个主题 | 展示一个地点的观察 |
| 阅读节奏 | 一张一张切换 | 连续向下浏览 |
| 默认说明 | 标题、时间，说明折叠 | 地点、张数 |
| 快速导航 | 底部缩略图带 | 滚动和位置计数 |
| 滚轮作用 | 换照片 | 滚动页面 |

## 10. 单张放大层、返回与 Info

### 放大图

点击照片后进入几乎满屏的观看层，主要只保留 Close 与品牌标记，消除标题、缩略图等干扰。URL 有独立照片地址，方便定位到具体作品。

但这里的「放大」不等于完整原图适屏：实际样式和截图显示，大图使用覆盖式呈现，竖图在横屏上会超出上下范围并被裁切。它适合强调局部冲击力，不适合默认保证完整构图。

测试中，普通 Series 浏览的方向键有效，但放大层内的右方向键没有切换照片。因此不要假定它有与你现有网站相同的「放大后左右箭头连续切图」能力。

从地点相册滚动到 `scrollY = 1300` 后打开照片，再按 Escape，实际返回保持在 `1300`。这种保留阅读位置的逻辑值得保留在我们自己的实现中。直接打开照片地址时的历史上下文与从相册进入不同，不能把两种返回场景混为一谈。

### Info

从栏目菜单打开 Info 时，桌面右侧约 55% 宽度的面板滑入，底层页面向左退开并降低存在感。关闭后回到原来的栏目。手机上则改为从顶部进入的纵向信息面板。[Info 内容](https://felixpeault.com/info)

内容顺序是作者身份与创作方向、拍摄类型、合作范围、社交与邮箱、代理信息、版权。没有重复铺很多照片。

## 11. 导航、动效与 UI 细节

### 导航策略

首页可直接看到 Series / Elsewhere / Info。进入作品区后，导航默认收起为当前栏目名称和点状符号；桌面悬停展开完整菜单，手机点击可以展开。

优点是少占画面。代价是入口不如常驻导航明显，初次访问者需要发现悬停或点击行为。

### 动效分工

- 首页：多张照片通过透明度、位置和缩放交接，营造动态选片印象。
- Series 目录：滚动时更新中心封面和文字，强化「一组一组看」。
- 系列详情：主图和当前缩略图同步更新。
- Details：说明层进入，底层内容下移并淡化。
- Info：侧滑面板与底层页面退让形成空间层级。
- 单张放大：从相册阅读切到更沉浸的图片状态。

公开 CSS 中，主要面板推移过渡约 1.2 秒，部分缩略图透明度过渡约 0.5 秒。不能把参考站所有动画统称为 0.5 秒淡入。

### 可借鉴的细节

- 图片默认没有持续显示的图名和说明，干扰较少。
- 计数与缩略图选中状态同时给方向感。
- 打开 Info 和照片时 URL 随状态变化，而不是完全不可定位的临时弹层。
- 根布局使用稳定的滚动条占位，减少开关覆盖层造成的页面横向跳动。
- 图像有尺寸和比例信息、响应式资源、优先加载与懒加载区分。

## 12. 技术实现观察与风险

### 已确认的公开实现线索

HTML 带有 SvelteKit 的标记与构建资源路径，图片来自 Sanity 图片 CDN；图像提供 `srcset`、`sizes`、不同宽度和自动格式参数。首页首图有优先加载，后续图片多为懒加载。

这解释了它为什么可以在总览放很多缩略图，同时为大图使用更清晰资源。真正需要借鉴的是资源分级，不是一定要迁移到同样的框架或 CMS。你的静态 GitHub Pages 仍可以实现相同的视觉和交互逻辑。

### 不宜照搬的部分

1. 满屏放大默认裁切，不符合你反复强调的完整图像比例要求。我们更适合默认完整适屏，再允许用户主动放大。
2. 缩略图按钮中有空文本且缺少明确辅助名称；小圆点也不够自解释。我们应提供可读标签、键盘焦点和足够点击面积。
3. 悬停发现式菜单对手机与首次访问者不够直观，不能只有 hover，没有点击入口。
4. 系列浏览接管滚轮，虽然有展览感，也可能让人误判滚动方向或触发连续跳图。必须限定作用范围，不能与主站整页吸附同时争抢滚轮。
5. 页面具有较强的自动轮播与推移动效。本次检查没有充分证据证明全站对减少动态效果偏好做了完整适配；我们需要单独实现并验收，而不是假定参考站已经处理好。
6. 窄粗字体、大字母品牌和蓝绿渐变是强烈的作者身份。原样复制会冲淡你现有的 Alice / Futura PT 和深红色体系。

## 13. 放到你的网站里，应该借鉴什么

以下是设计建议，不是已经实施的修改。

### 13.1 保留双作品集入口，不再增加一层封面

建议路径：

```text
现有视频封面
  Profile
  Portfolio 选择
    Architecture：保留现有项目浏览
    Photography：直接进入摄影作品目录
      Series：主题系列
      Places：地点归档，可后续增加
      相册 / 系列详情
      单张照片查看
```

Photography 应当有自己的作品浏览语言，但不需要重新介绍一次你是谁。现有 Profile、CV 和 Contact 可以共用。

### 13.2 视觉上保持同一个人，观看方式可以不同

保留 Alice 作为个人名字的标识，Futura PT 作为信息字体，沿用现有主题色。摄影区域可以比建筑区域少很多文字，把面积交给图像。

不建议直接复制 F/P 大字母，也不建议未经讨论新增蓝绿色渐变。可以先在现有浅底上验证照片和排版是否成立，再决定摄影分支是否需要独立的色彩表现。

### 13.3 摄影元信息不要沿用建筑项目字段

建筑项目里的 Role、Architect、Status 等字段不适合成为每个摄影系列的固定信息。摄影优先保留：系列标题、地点、年份或时间范围、照片数量、可选的短介绍。相机和镜头信息不需要默认出现。

### 13.4 照片排序是内容工作，不宜随机

参考站的价值在于编排。建议摄影系列手动排序，安排开场、转折、停顿和收尾；地点归档也需要筛选。不要直接沿用建筑 Gallery 曾使用的随机顺序。

### 13.5 首版建议从一条路径做完整

我的优先建议是先做 Series：摄影目录、系列详情、单张查看、返回定位和手机布局都完成，再决定是否有足够内容支持 Places 归档。

这能避免摄影数量不多时，目录看起来很复杂，但每个分类只有少量照片。若你的现有照片主要按旅行地点整理，顺序可以反过来，先做 Places；关键由内容决定，而不是为复制参考站凑分类。

## 14. 后台需要对应的内容能力

现有本地后台已经有摄影项目分类和图片管理，但要承载上述设计，还需要明确区分「摄影系列」和「地点集合」的呈现方式，不能把建筑项目表单原封不动当作最终摄影编辑器。

建议未来字段：

| 内容单位 | 建议字段 |
| --- | --- |
| 集合 | 标题、稳定 ID、类型、封面、地点、年份、介绍、显示顺序 |
| 照片 | 文件、可选图名、替代文字、拍摄地点、手动顺序 |
| 展示选项 | 单张切换 / 连续滚动、是否显示介绍、封面焦点 |

照片数量由系统计算，不手工填写。图名可以只在放大或需要时出现；替代文字仍应保留。上传时自动生成缩略图和大图版本，避免目录加载原始高清文件。

## 15. 下一轮讨论的四个决定

1. 内容入口：先按主题 Series，还是先按地点 Places？
2. 详情观看：单张切换，还是自然连续滚动？可以按集合类型区分，但首版不必全做。
3. 视觉身份：摄影是否沿用现有浅底与深红色，还是需要一个独立但相关的配色？
4. 导航关系：摄影内保留多少主站导航，以及从相册回到 Photography、Portfolio 选择和 Architecture 的路径。

我的整体建议：学它如何让观众看照片，而不是只学它看起来像什么。先把内容分组和浏览节奏定下来，再微调字体、颜色与动画。
